Why No-Code Model Training & Quality Control?

Once library datasets are cleaned (Module 2) and annotated (Module 4), librarians can move beyond general-purpose commercial chatbots to fine-tune custom, domain-specific Large Language Models (LLMs). Using no-code / low-code frameworks like Llama Factory, library staff can fine-tune LLMs, evaluate performance, deploy, and monitor custom models without complex coding.

Module Goal: Learners practice fine-tuning a custom "Library Ticket Classifier" LLM model using Llama Factory, evaluating model performance with quantitative metrics and a Confusion Matrix, calling LLM models via the OpenAI API for seamless code integration, exploring AI governance and model drift monitoring, and directing an autonomous Library Workshop Planner Agent in Google Antigravity to automate constraint-checked event planning.

This module provides academic librarians and library managers with the strategic and operational skills needed to oversee AI training pipelines, interpret quality metrics, and enforce ongoing AI governance in library systems.

The LLM Fine-Tuning & Quality Control Workflow

This module follows a 6-step operational lifecycle for non-coding library managers and specialists:

1. Upload Data

Import clean, labeled dataset (e.g., 200 labeled Library Support Tickets) into the training environment.

2. Fine-Tune LLM

Configure training parameters in Llama Factory to fine-tune foundation models (e.g. LLaMA, Qwen) for library tasks.

3. Evaluate Metrics

Analyze quantitative metrics: Accuracy, Precision, Recall, and F1-Score to assess model quality.

4. Diagnose Errors

Inspect the Confusion Matrix to identify where the AI gets confused between categories.

5. OpenAI API Integration

Call fine-tuned or hosted LLM models via OpenAI API endpoints for interactive testing and code integration.

6. Govern & Monitor

Establish dashboards to track performance over time, detect model drift, and prevent bias.

Task 2: Understanding Evaluation Metrics & Dashboard Analysis

Evaluating AI models requires moving beyond simple qualitative impressions ("it looks right") to hard quantitative data. Training dashboards in Llama Factory and cloud platforms present core evaluation metrics.

Accuracy

Overall percentage of tickets correctly classified across all categories.

Correct Predictions / Total Tickets

Precision

Of all tickets flagged as "Technical Issue", how many were actually technical issues? (Measures exactness / low false alarms).

True Positives / (True Positives + False Positives)

Recall

Of all actual "Technical Issue" tickets, how many did the AI successfully catch? (Measures completeness / low missed tickets).

True Positives / (True Positives + False Negatives)

F1-Score

The harmonic mean of Precision and Recall, providing a single balanced quality metric.

2 * (Precision * Recall) / (Precision + Recall)

Dashboard Diagnostics: The Confusion Matrix

A Confusion Matrix is a diagnostic grid showing where the model succeeds and where it confuses labels. Below is the evaluation result for our fine-tuned model on test samples:

Task 4: AI Governance, Model Drift & Quality Control

Deploying a model is not the end of the AI lifecycle. Over time, AI models can suffer from Model Drift—a decline in accuracy caused by changing user terminology, new library services, or shifting vocabulary.

Data & Concept Drift

When the library introduces a new authentication system (e.g. switching from EZproxy to OpenAthens), patrons submit new terms. Without retraining, the AI's accuracy degrades over time.

Bias & Fairness Auditing

Ensuring the ticket classifier treats patron inquiries equitably regardless of phrasing, language background, or academic department.

Library AI Governance Checklist

  • Monthly Performance Audit: Sample 50 live tickets to recalculate Precision, Recall, and F1 scores.
  • Human-in-the-Loop Safeguard: Automatically route low-confidence predictions (< 75% score) to human staff.
  • Retraining Schedule: Update training datasets quarterly with new vocabulary and newly resolved tickets.
  • Privacy Compliance: Ensure patron names, ID numbers, and sensitive text are scrubbed before model training.

Task 5: Agentic AI & Workflow Automation with Google Antigravity

Beyond traditional model fine-tuning and passive chatbots, modern library managers can leverage Agentic AI platforms like Google Antigravity to automate complex, multi-step operational workflows. While standard conversational LLMs merely generate text and often hallucinate mathematical calculations, an autonomous AI agent can perceive a local workspace, read structured files, run deterministic terminal scripts to verify constraints, generate production-ready documentation, and dynamically adapt to changing requirements under human supervision.

Two-Round Interactive Agentic Workflow

In Google Antigravity, library staff can open the librarian-agent-demo folder, open the built-in Agent Chat, and interact with the agent across multiple turns. Watch how the agent uses tools deterministically rather than making guesses:

Round 1 Initial Proposal Generation (20 Attendees, $80 Budget)
Initial Planning

Paste the following prompt into the Antigravity Agent Chat:

Read AGENTS.md and act as my Library Workshop Planner.
Plan a 60-minute AI basics workshop for 20 adult library patrons with an $80 budget.
Read the project data, run check_plan.py, and select a feasible room.
Include refreshments if they fit the budget.
Save a detailed proposal to output/event_plan.md, including an itemized budget and a 60-minute agenda.
Explain your tool actions briefly. Label the plan as a proposal, not a confirmed booking.

🤖 What Google Antigravity Does Autonomously:

  1. Reads workspace configuration AGENTS.md, data/request.json, data/rooms.csv, and data/policy.json.
  2. Executes terminal command: python3 check_plan.py.
  3. Evaluates checker output: Reading Room is selected (Capacity 24 ≥ 20, projector available, step-free access compliant).
  4. Calculates itemized budget: $0 room fee + $40 materials ($2 × 20) + $20 refreshments ($1 × 20) = $60.00 (under the $80 budget cap).
  5. Writes full proposal to output/event_plan.md with a 60-minute timed agenda and accessibility guidance, marking it clearly as an unconfirmed proposal.
Round 2 Dynamic Constraint Revision (35 Attendees, $100 Budget, No Refreshments)
Human-in-the-Loop Feedback

In the same Antigravity chat session, the librarian requests changes due to higher demand:

Let's revise the workshop plan.
We now expect 35 attendees, and the approved budget is $100.
Remove refreshments, but keep the 60-minute duration, projector requirement, and step-free access.
Run check_plan.py again with the updated inputs.
Select a suitable room and update output/event_plan.md with the new budget and agenda.
Do not claim the room is booked.

🤖 What Google Antigravity Does Autonomously:

  1. Executes constraint tool with updated arguments: python3 check_plan.py --attendees 35 --budget 100.
  2. Diagnoses room constraints: Reading Room fails (capacity 24 < 35); Study Room fails (capacity 12 < 35 and no projector).
  3. Selects Community Hall: Capacity 40 ≥ 35, projector: yes, step-free: yes. Budget: $30 room fee + $70 materials ($2 × 35) + $0 refreshments = $100.00 (exact match to $100 budget cap).
  4. Updates output/event_plan.md with new room specifications, adjusted itemized table, and updated 60-minute agenda scaled for 35 attendees.

Deterministic Grounding

Rather than having the LLM guess whether 35 people fit into a room or perform mental math on catering costs, Antigravity executes check_plan.py, ensuring 100% compliance with institutional rules.

Markdown Instructions (AGENTS.md)

System prompts are maintained in version-controlled markdown files (AGENTS.md), enabling library teams to collaboratively govern agent personas, output styles, and constraint limits.

Human-in-the-Loop Governance

The agent operates as a planning assistant that drafts proposals and identifies blockers. Real-world bookings, contracts, and budget allocations remain firmly under human librarian control.
