Why No-Code Model Training & Quality Control?

Once library datasets are cleaned (Module 2) and annotated (Module 4), librarians can move beyond general-purpose commercial chatbots to train custom, domain-specific AI models. Modern Automated Machine Learning (AutoML) platforms allow library staff to build, evaluate, deploy, and monitor custom classifiers without writing code.

Module Goal: Learners practice training a custom "Library Ticket Classifier" using Hugging Face AutoTrain, evaluating model performance with quantitative metrics and a Confusion Matrix, testing deployed endpoints on Vertex AI / Hugging Face, and exploring AI governance and model drift monitoring.

This module provides academic librarians and library managers with the strategic and operational skills needed to oversee AI training pipelines, interpret quality metrics, and enforce ongoing AI governance in library systems.

The AutoML & Quality Control Workflow

This module follows a 6-step operational lifecycle for non-coding library managers and specialists:

1. Upload Data

Import clean, labeled dataset (e.g., 200 labeled Library Support Tickets) into the AutoML platform.

2. Auto-Train

Configure task parameters; the platform automatically tests, tunes, and selects the optimal algorithms.

3. Evaluate Metrics

Analyze quantitative metrics: Accuracy, Precision, Recall, and F1-Score to assess model quality.

4. Diagnose Errors

Inspect the Confusion Matrix to identify where the AI gets confused between categories.

5. Deploy Endpoint

Publish the model endpoint to Vertex AI or Hugging Face Spaces for real-time testing and inference.

6. Govern & Monitor

Establish dashboards to track performance over time, detect model drift, and prevent bias.

Task 1: Auto-Training a Text Classifier with Hugging Face AutoTrain

Automated Machine Learning (AutoML) automates the complex process of model architecture selection, hyperparameter tuning, and validation. In this task, learners use Hugging Face AutoTrain to build a custom text classification model without writing a single line of code.

Hands-on Auto-Training Steps

  1. Log into Hugging Face AutoTrain and create a new Text Classification project.
  2. Upload the labeled CSV dataset of 200 Library Support Tickets.
  3. Map the columns: set text as input and target (category label) as target.
  4. Click Start AutoTrain to launch automatic candidate training.
  5. Review candidate model rankings based on validation scores.

Teaching Point for Librarians

AutoML allows librarians to focus on domain data quality and task definition rather than hyperparameter tuning. The platform tests multiple transformer architectures (e.g., BERT, RoBERTa, DistilBERT) automatically.

Task 2: Understanding Evaluation Metrics & Dashboard Analysis

Evaluating AI models requires moving beyond simple qualitative impressions ("it looks right") to hard quantitative data. AutoTrain and Vertex AI present dashboards with core evaluation metrics.

Accuracy

Overall percentage of tickets correctly classified across all categories.

Correct Predictions / Total Tickets

Precision

Of all tickets flagged as "Technical Issue", how many were actually technical issues? (Measures exactness / low false alarms).

True Positives / (True Positives + False Positives)

Recall

Of all actual "Technical Issue" tickets, how many did the AI successfully catch? (Measures completeness / low missed tickets).

True Positives / (True Positives + False Negatives)

F1-Score

The harmonic mean of Precision and Recall, providing a single balanced quality metric.

2 * (Precision * Recall) / (Precision + Recall)

Dashboard Diagnostics: The Confusion Matrix

A Confusion Matrix is a diagnostic grid showing where the model succeeds and where it confuses labels. Below is the evaluation result for our 200 Library Support Tickets:

Actual Label \ Predicted Pred: Technical Issue Pred: Account Inquiry Pred: Reference Question
Actual: Technical Issue 64 (Correct) 5 (Mistake) 1
Actual: Account Inquiry 8 (Confusion!) 54 (Correct) 3
Actual: Reference Question 2 2 61 (Correct)

Diagnostic Insight: Notice that the model frequently mistakes Account Inquiries for Technical Issues (8 cases). For example, a ticket saying "I can't log in to see my loans" mentions "log in" (technical keyword) but relates to patron accounts. This insight tells librarians to add more specific training examples clarifying login-related account inquiries!

Task 4: AI Governance, Model Drift & Quality Control

Deploying a model is not the end of the AI lifecycle. Over time, AI models can suffer from Model Drift—a decline in accuracy caused by changing user terminology, new library services, or shifting vocabulary.

Data & Concept Drift

When the library introduces a new authentication system (e.g. switching from EZproxy to OpenAthens), patrons submit new terms. Without retraining, the AI's accuracy degrades over time.

Bias & Fairness Auditing

Ensuring the ticket classifier treats patron inquiries equitably regardless of phrasing, language background, or academic department.

Library AI Governance Checklist

  • Monthly Performance Audit: Sample 50 live tickets to recalculate Precision, Recall, and F1 scores.
  • Human-in-the-Loop Safeguard: Automatically route low-confidence predictions (< 75% score) to human staff.
  • Retraining Schedule: Update training datasets quarterly with new vocabulary and newly resolved tickets.
  • Privacy Compliance: Ensure patron names, ID numbers, and sensitive text are scrubbed before model training.

Task 5 (Exploratory): Agentic AI & Task Automation with Amazon Q

In addition to model training, modern library managers can explore Agentic AI and Auto-Programming tools like Amazon Q Developer to automate repetitive operational tasks via natural language prompts.

Automation Experiment: Learners enter natural language instructions into an AI assistant to auto-generate library workflow scripts (e.g., "Write a workflow to parse incoming CSV book lists by ISBN and highlight missing catalog entries" or "Trigger an alert when support ticket backlog exceeds 20 items").

This connects traditional model classification with agentic workflow automation, preparing librarians for end-to-end service integration (Module 6).
